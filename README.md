# Лонгбокс

Лёгкий дашборд-каталог комиксов с публичной витриной, запароленной CMS и встроенной аналитикой популярности. Рассчитан на слабый сервер: один процесс, файловая БД SQLite, агрессивное кэширование статики.

## Возможности

**Публичная часть**
- Сетка серий с превью, статус-плашкой и счётчиком просмотров. У каждой серии два названия — русское (приоритетное) и оригинальное; в списках показываются оба.
- Модалка серии (через *shallow routing*): описание, авторы, издательство, вселенная, статус, список релизов. Открывается поверх каталога, при этом `/series/<slug>` — рабочая прямая ссылка.
- Релиз — это отдельный **выпуск** или собранный **том**; у серии могут быть и те, и другие одновременно (на детальной странице они в отдельных секциях).
- Кликабельные издательство / вселенная / автор → автоматически применяют фильтр каталога.
- Фильтры (издательство, вселенная, статус, автор), полнотекстовый **поиск** по обоим названиям и описанию (SQLite FTS5, кириллица + префиксы), сортировка, **пагинация**.
- Ссылки на скачивание проходят через редирект-эндпоинт, который логирует клик.
- Ленивая загрузка обложек, `ETag` + долгий immutable-кэш для картинок, короткий кэш списка.

**CMS (только администратор)**
- Вход по паролю из переменной окружения `ADMIN_PASSWORD`. Защита от перебора: после 5 неудачных попыток IP блокируется на 15 минут (in-memory).
- CRUD серий, управление релизами (выпуск/том), загрузка обложек (сжатие в WebP через `sharp`).
- Издательства/вселенные/авторы создаются автоматически при заполнении формы; отдельная страница «Справочники» для переименования/удаления.

**Аналитика (только администратор)**
- Просмотры, скачивания, уникальные посетители (псевдонимный хэш) за период (7/30/90/365 дней).
- График динамики, топ серий и топ выпусков по скачиваниям.

## Стек

SvelteKit (adapter-node, SSR) · better-sqlite3 (WAL) · FTS5 · sharp · Tailwind CSS. Без внешней БД и лишних рантаймов — единый Node-процесс.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `ADMIN_PASSWORD` | **Обязательно.** Пароль входа в CMS. |
| `SESSION_SECRET` | **Обязательно (prod).** Секрет для подписи сессионной cookie. |
| `ORIGIN` | Публичный origin, напр. `https://comics.example.com`. **Нужен для adapter-node**, иначе POST-формы (вход, CMS) отклоняются CSRF-защитой. |
| `DATA_DIR` | Каталог данных (БД + обложки). По умолчанию `./data`. |
| `PORT` | Порт прод-сервера. По умолчанию `3000`. |
| `BODY_SIZE_LIMIT` | Лимит размера запроса (загрузка обложек). По умолчанию `8M`. |

## Локальная разработка

```bash
npm install
cp .env.example .env        # задайте ADMIN_PASSWORD и т.д.
npm run seed                # справочник издательств (~60 шт., US + BD; идемпотентно)
npm run dev                 # http://localhost:5173
```

Прод-сборка без Docker:

```bash
npm run build
ADMIN_PASSWORD=... SESSION_SECRET=... ORIGIN=http://localhost:3000 node build
```

## Запуск в Docker

Образ один и тот же для локали и сервера.

```bash
# 1. Создайте .env рядом с docker-compose.yml:
#    ADMIN_PASSWORD=...
#    SESSION_SECRET=...   (например: openssl rand -hex 32)
#    ORIGIN=http://localhost:3000   (или ваш домен в проде)

docker compose up -d --build       # http://localhost:3000
docker compose run --rm app npm run seed   # справочник издательств (идемпотентно, можно на проде)
docker compose logs -f app
```

Данные (SQLite + обложки) хранятся в именованном volume `comic_data` и переживают пересоздание контейнера. Контейнер работает от non-root пользователя, лимит памяти — 384 МБ (правится в `docker-compose.yml`).

> Полная пошаговая инструкция для удалённого сервера (домен, TLS, прокси, бэкапы) — в [DEPLOY.md](DEPLOY.md).

### Прод за обратным прокси

Поставьте Caddy/Nginx перед контейнером, терминируйте TLS на прокси и пробросьте заголовки. Обязательно задайте `ORIGIN` = ваш публичный HTTPS-адрес. Пример Caddy:

```
comics.example.com {
    reverse_proxy 127.0.0.1:3000
}
```

## Скачиваемые файлы

Поле «Ссылка на скачивание» у выпуска ведёт на **внешний** источник — файлы комиксов сервером не хостятся (это сознательно: бережёт диск и трафик слабого сервера). Клик идёт через `/api/dl/<id>`, который пишет событие и редиректит на ссылку.

## Резервное копирование

Вся БД — один файл `DATA_DIR/comics.sqlite` (+ `-wal`/`-shm`). Бэкап:

```bash
docker compose exec app sh -c "cp /data/comics.sqlite /data/backup-$(date +%F).sqlite"
# либо скопировать volume comic_data целиком
```

## Структура

```
src/
  lib/
    components/        UI: карточка, фильтры, пагинация, модалка, форма CMS, график
    server/
      db/              подключение SQLite, schema.sql (+ FTS5), seed
      queries.ts       чтение каталога (список/фильтры/поиск/деталь)
      cms.ts           мутации CMS (серии/выпуски/справочники)
      analytics.ts     запись событий + агрегаты
      auth.ts          сессия админа (HMAC-cookie)
      images.ts        сжатие обложек (WebP)
  routes/
    +page.*            каталог + модалка
    series/[slug]/     страница серии (прямая ссылка)
    api/dl/[issueId]/  редирект скачивания + лог
    covers/[file]/     отдача обложек (ETag/кэш)
    admin/             CMS: dashboard, series, meta, stats, login
```
